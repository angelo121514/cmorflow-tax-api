## Mapa por módulo

- **Controllers y contratos HTTP:** src/controllers/** y src/controllers/dtos/**.
- **Casos de uso DTE:** src/application/dte/**.
- **Integraciones/cola/webhooks/RCOF:** src/application/integrations/**.
- **Entidades de dominio:** src/domain/entities/**.
- **Infraestructura PostgreSQL:** src/infrastructure/framework/postgres/**.
- **Motor tributario/SII/artefactos:** src/infrastructure/framework/sii/**.
- **Auth, cifrado y config:** src/infrastructure/guards/**, src/infrastructure/framework/crypto/**, src/infrastructure/config/**.
- **Schema:** src/database/migrations/** y src/infrastructure/framework/postgres/entities/**.
- **Configuración y despliegue:** package.json, .env.example, Dockerfile, docker-compose.yml, render.yaml, .github/workflows/**.

- Para cambios nuevos usar [CHANGE_TEMPLATE.md](CHANGE_TEMPLATE.md); CI valida los IDs, matrices, riesgos y contrato OpenAPI.

## Uso para cambios futuros

Partir de la fila Feature, leer la ruta en API_SPEC y sus reglas en BUSINESS_RULES. Confirmar el test indicado en TESTING y actualizar TRACEABILITY si cambia API, dominio, storage o comportamiento. Cambios en emisión deben revisar también cálculo/serialización XML y validación SII.

## Referencias verificables y cambios

CI comprueba que los enlaces a specs, código y tests existen. Para cada cambio relevante se exige una ficha nueva o actualizada en changes/ que declare los archivos del diff. Consulta [CONTRIBUTING.md](../../CONTRIBUTING.md) para el procedimiento y comandos.
