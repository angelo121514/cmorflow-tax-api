# Reglas de negocio observadas

Cada regla refleja el código local, no una validación legal externa.

| ID    | Regla y resultado                                                                                                           | Condiciones/excepciones                                                                                                                                       | Ubicación                                                                              |
| ----- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| BR-01 | Emisión estándar admite 33, 34, 39, 41, 46, 52; 56/61 usan rutas dedicadas.                                                 | Tipos restantes producen validación.                                                                                                                          | create-integration-dte.dto.ts; integration-request.service.ts; dtes.controller.ts      |
| BR-02 | Receptor RUT/nombre requerido para 33/34/46/52.                                                                             | Boletas 39/41 lo permiten ausente; motor rellena receptor genérico.                                                                                           | integration-request.service.ts; dte-xml.engine.ts                                      |
| BR-03 | Tipos 34/41 requieren todos los ítems exentos; tipo 39 no admite exentos.                                                   | 41 es boleta exenta.                                                                                                                                          | integration-request.service.ts                                                         |
| BR-04 | Tipo 52 exige transport.transferType.                                                                                       | DTO de transporte admite origen/destino, vehículo y transportista.                                                                                            | integration-request.service.ts; emit-dte.dto.ts                                        |
| BR-05 | Tipo 46 requiere autorización especial en emisión real.                                                                     | Perfil debe indicar canIssueT46.                                                                                                                              | emit-dte.use-case.ts; dte-domain-rules.ts; tenant-config.service.ts                    |
| BR-06 | Cantidad positiva, precio no negativo, nombre de línea máx. 80 caracteres, máx. 1000 ítems.                                 | DTO público y validación propia cubren estos campos.                                                                                                          | create-integration-dte.dto.ts; integration-request.service.ts                          |
| BR-07 | Línea no combina descuento porcentual/fijo; porcentaje 0–100 con hasta 2 decimales; descuento fijo no supera importe bruto. | El engine valida descuentos.                                                                                                                                  | discount.engine.ts y DTOs.                                                             |
| BR-08 | Servidor recalcula totales y no confía en montos del cliente.                                                               | Totales declarados opcionales toleran diferencia de 1 CLP; IVA 19%, redondeo CLP, descuento global afecta solo a afectos y retenciones bajan total.           | integration-request.service.ts; discount.engine.ts; dte-xml.engine.ts                  |
| BR-09 | Pricing admite GROSS y NET.                                                                                                 | DiscountEngine interpreta opción omitida como NET; el DTO describe default por tipo. El default contractual por tipo debe validarse de punta a punta.         | create-integration-dte.dto.ts; discount.engine.ts; dte-xml.engine.ts                   |
| BR-10 | Nota 56/61 necesita referencia y se emite por ruta dedicada.                                                                | Controller obtiene datos del original y valida pertenencia al tenant.                                                                                         | dtes.controller.ts; integration-request.service.ts                                     |
| BR-11 | Idempotencia por tenant/kind/recurso/key y hash de body crudo.                                                              | Mismo hash devuelve snapshot; distinto body da 409; externalReference reutilizada con otra key da 409. Se exige key no vacía, no UUID.                        | integration-request.service.ts; integration-controller.helper.ts; migración 180560.    |
| BR-12 | Un DTE ya preparado para request no debe reservar segundo folio al reintentar.                                              | processor conserva dteId tras prepare. Fallo antes de persistir DTE puede ocurrir tras reservar folio.                                                        | integration-processor.service.ts; emit-dte.use-case.ts; tenant-config.service.ts       |
| BR-13 | Reserva atómica escoge CAF disponible para tipo y avanza lastUsedFolio.                                                     | Error si falta config, CAF de tipo o folios disponibles. Fija tenant en misma transacción.                                                                    | tenant-config.service.ts; caf.engine.ts                                                |
| BR-14 | RCOF es idempotente por tenant/fecha/secuencia; consolida boletas 39/41 no borrador.                                        | Fecha YYYY-MM-DD; sin boletas devuelve 422; anuladas cuentan en montos/total emitidas, no en folios activos.                                                  | generate-rcof.use-case.ts; rcof.controller.ts                                          |
| BR-15 | Rotación de credencial deja la anterior válida máximo 24h; revocación es inmediata.                                         | No se puede revocar última admin activa ni a sí misma.                                                                                                        | integration-credentials.use-case.ts                                                    |
| BR-16 | Credencial `api` no puede recibir permisos administrativos, incluidos webhooks:read/write y credentials:read/write.         | Se valida por tipo al crear credenciales; GET webhooks además exige webhooks:read.                                                                            | integration-credentials.use-case.ts; integration-errors.ts; docs/integrations/GUIDE.md |
| BR-17 | Perfil visual versionado/inmutable; PNG/JPEG entrante se normaliza a PNG.                                                   | Logo obligatorio por PUT aunque puede ser null; máximo 700 KiB entrada, 4 MP, 512 KiB salida; contraste primario 4.5:1 con blanco.                            | invoice-branding.service.ts; migración 180570.                                         |
| BR-18 | Estado B2B sigue máquina explícita; cambios notificables crean webhook.                                                     | `observed` se sigue consultando por TrackID y puede transicionar a accepted/rejected; nunca retransmite automáticamente el DTE observado.                     | integration-state.service.ts; integration-processor.service.ts                         |
| BR-19 | URL de webhook exige HTTPS y no debe resolver a red privada/local.                                                          | No sigue redirects; timeout cubre headers y body, y el snippet leído está limitado a 300 bytes.                                                               | integration-webhook.service.ts                                                         |
| BR-20 | Runtime producción rechaza config incompleta, master key débil, modo SII mock, XSD desactivado o DB sin SSL verificado.     | Validación se ejecuta antes de API, worker y migrador.                                                                                                        | runtime-config.ts; main.ts; worker.ts; migrate.ts                                      |
| BR-21 | `Idempotency-Key` es una cadena opaca no vacía, scoped por tenant, tipo y recurso.                                          | Se persiste sin normalización; mismo hash hace replay y hash distinto devuelve 409. Los conflictos concurrentes consultan la fila ganadora del índice unique. | integration-request.service.ts; integration-controller.helper.ts                       |
| BR-22 | RCOF diario es una solicitud durable, recuperable y rastreable como RCOF manual.                                            | Se encola con clave estable por fecha/secuencia y sin credencial API; un replay no genera segunda fila.                                                       | integration-orchestrator.service.ts; integration-request.service.ts; migración 180580  |
| BR-23 | `dte:cancel` no se otorga en API v1 hasta que exista ruta y flujo tributario aprobados.                                     | Se conserva `cancelled` como estado interno, pero el permiso ya no forma parte del catálogo v1.                                                               | integration-errors.ts; DECISIONS.md                                                    |

Las reglas tributarias anotadas por código deben validarse contra normativa y certificación vigente antes de tratarlas como autoridad legal.
