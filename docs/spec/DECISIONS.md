# Decisiones SDD

Registro de decisiones que condicionan el contrato o los flujos. Una decisión tributaria sólo se considera aprobada con referencia/evidencia vigente y responsable identificable.

| ID    | Decisión                                                                                                                                                                                              | Estado                                 | Responsable                | Evidencia/motivo                                                                                                                       |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| D-001 | Solicitudes DTE `observed` se siguen consultando por el mismo TrackID; nunca se retransmiten automáticamente. Sólo se transiciona a `accepted`/`rejected` si SII devuelve ese estado.                 | Aprobada para v1                       | Backend                    | Máquina de estados permite observed→accepted/rejected; evita duplicar folio/envío.                                                     |
| D-002 | RCOF diario se crea como `integration_request` persistida, con `origin_credential_id` nulo y clave determinista por fecha/secuencia; processor y poller estándar lo recuperan tras reinicio.          | Aprobada para v1                       | Backend + Operaciones      | Misma cola durable y misma unicidad de negocio que RCOF manual.                                                                        |
| D-003 | Cancelación DTE no se expone ni se concede como permiso v1 hasta validar flujo y semántica con SII.                                                                                                   | Aprobada como límite v1                | Producto + Tributario      | No existe endpoint; estado `cancelled` se conserva para compatibilidad interna.                                                        |
| D-004 | `webhooks:read` es permiso administrativo y sólo se concede a credencial `admin`.                                                                                                                     | Aprobada para v1                       | Seguridad + Backend        | Alinea creación de credenciales con los endpoints administrativos y la guía.                                                           |
| D-005 | `Idempotency-Key` es opaca y no vacía; no se requiere UUID. Se persiste tal cual y se vincula al hash del body dentro de tenant/kind/resource. PostgreSQL `varchar` no añade un máximo de aplicación. | Aprobada para v1                       | Producto + Backend         | Evita estrechar el contrato existente; UUID queda como recomendación del cliente, no requisito. Se aplica el límite HTTP para headers. |
| D-006 | Regla del total T46 con retenciones y validación quirúrgica/XSD.                                                                                                                                      | Bloqueada                              | Responsable tributario/SII | No cambiar cálculo ni regla de preflight hasta recibir confirmación documentada y fixture autorizado.                                  |
| D-007 | Provisioning inicial de tenants es externo a esta API; no se añade ruta de creación.                                                                                                                  | Bloqueada para procedimiento operativo | Operaciones + Producto     | El checkout no contiene endpoint ni runbook aprobado con responsables/sistema fuente.                                                  |
